Internet 的 **网络层（Network Layer）** 主要负责“把数据从源主机跨网络传到目标主机”，它是整个互联网通信中负责**端到端路径选择与转发**的核心层。
- 网络层协议存在于每一个互联网设备：**主机和路由器**
- **发送方主机网络层的作用**：将来自运输层的每个报文段封装成一个数据报（网络层分组）； 将数据报向目的地发送，即向相邻的路由器R1发送。
- **接收方主机网络层的作用**：接收来自相邻的路由器R2的数据报； 解封出报文段，并交付给其运输层。
- **路由器的主要作用**： 将数据报从输入链路“转发”到输出链路。 通常路由器只实现下三层部分。

# 两个关键功能

- **转发** （数据平面）：将分组从**路由器的输入链路转发到合适的输出链路**
- **路由** （控制平面）: 使用路由算法来**确定分组从发送主机到目标接收主机的路径** （路由算法，路由协议）

- 两者区别：
	- 转发：将分组从路由器的一个输入链路接口转移到一个合适的输出链路接口的本地动作。 只**涉及分组在路由器中从入链路到出链路的传送**
	- 路由：指分组从源到目的地的端到端路径的网络范围动作。 **涉及网络中的所有路由器**，集体经选路协议交互，决定分组从源到目的地的路径。

# 分组交换机

- 分组交换机：一台通用分组交换设备，**根据分组首部值，从输入链路接口到输出链路接口传送分组。**
- 链路层交换机：**根据链路层字段值作转发决定**的分组交换机。 
- 路由器**：根据网络层字段值作转发决定**的分组交换机。

# 网络服务模型

- 定义在网络的一侧“边缘”到另一侧“边缘”之间（即在发送与接收端系统之间）**端到端的数据运输特性**。
- **确保交付**：确保分组到达目的地。
- **具有时延上界的确保交付**：主机到主机的时延。
- **有序分组交付**：按发送顺序到达。
- **确保最小带宽**：当发送主机以低于特定比特率的速率发送比特，分组不会丢失，在一定时延到达。、
- **确保最大时延抖动**：发送方发送两个连续分组的时间间隔与接收到的间隔相同。


## Internet服务模型-尽力而为

- 没有对以下指标提供任何保障: 
	- 数据包是否能够成功交付到目标主机 
	- 延迟以及交付的顺序 
	- 端到端流的可用带宽

## ATM服务模型

提供多重的服务模型，即在同一网络中为不同的连接提供不同类别的服务。

### 恒定比特率CBR(Costant bit rate)服务

- 使网络连接看起来就像在发送主机和接收主机之间**有一条专用的固定带宽的传输链路**。
- ATM信元传输时的端到端时延可变性(时延抖动)及丢失、迟交的信元都保证在规定值以下。

### 可用比特率ABR (Available bit rate)服务

“比尽力服务稍好一点”的服务。
- 可能会丢失信元，但不能被重排序；
- 保证最小信元传输速率(MCR)，或比MCR更高（有足够空闲资源）； 
- 能够为发送方提供反馈信息。

# 虚电路网络

- **虚电路网络**是一种在发送数据前**必须先“拨号”建立连接的面向连接**的网络模式。它通过**在源和目的地之间建立一条逻辑上的专属通道**，让所有携带简短数字标签（VCID）的数据包都必须严格沿着这条预定路径按顺序排队前行，从而保证了数据传输的高速、不乱序和稳定的服务质量；但其缺点在于极度依赖沿途节点的稳定性，一旦中间有路由器故障，整条虚电路就会崩溃瘫痪。
- **典型代表**：**ATM（异步传输模式）**、**X.25**、**帧中继（Frame Relay）**。

## 虚电路（VC）组成

- **源和目的地之间的一条连接路径**：一系列链路和路由器； 
- **VC号**：该路径上每段链路的号码，每条链路上的VC号可能不同； 
- **路由器转发表中的表项**：VC路径上每台路由器中都有该表。

## 工作原理

- 在源和目的之间创建一个VC；
- 源向该VC发送带有VC号的分组；
- 每经过一台中间路由器，**用新的VC号代替原VC号**：从VC号转发表获得；
- 分组在每条链路上的VC号不同。
- 依此规则，直到目的地。
- 即建立电路，数据传输，销毁电路

## VC号转发表

- VC号转发表（Virtual-Circuit Forwarding Table）是**路由器进行数据转发**的核心依据。
- 同一条虚电路，**在不同的链路上，其 VC 号通常是不同的。**
- **路由器维护连接状态信息**
	- 只要该路由器创建新的VC，其转发表中就增加一项；
	- 终止一个VC，其转发表中就删除对应项。
	- 路由器必须为正在进行的连接维护连接状态信息，直到该连接释放。 
- **每条链路采用不同VC号的优点**：
	- 减少分组首部VC字段的长度；
	- 简化虚电路的建立过程。

- 转发表的结构非常精简，它由 **4 个核心列（字段）** 组成：

| **输入接口 (In-Interface)** | **输入 VC 号 (In-VCID)** | **输出接口 (Out-Interface)** | **输出 VC 号 (Out-VCID)** |
| ----------------------- | --------------------- | ------------------------ | ---------------------- |
| 数据包进入路由器的物理端口           | 数据包头部当前携带的标签号         | 数据包应该被送出的物理端口            | 数据包出发前需要换上的**新标签号**    |

### 标签交换过程

假设某台路由器的转发表中有一行数据如下：

$$\text{[ 接口 1, \ VC 号 12 ]} \longrightarrow \text{[ 接口 3, \ VC 号 22 ]}$$

1. **匹配**：一个数据包从路由器的 **接口 1** 挤进来，路由器看了一眼它的包头，发现上面写着 VC 号 **12**。
2. **转换（Label Switching）**：路由器立刻用新标签 **22** 替换掉原本的 **12**。
3. **转发**：路由器直接把这个换好标签的数据包从 **接口 3** 发射出去。

## 虚电路建立阶段

- 在发送方与接收方之间建立一条虚电路，即**决定所有分组要通过的一系列链路与路由器，并为每条链路确定一个VC号**。
- 主机 A 生成一个特殊的信令包，叫做 **“呼叫请求（Call Request）”**。
- 当呼叫请求包沿着网络一站一站向前推进时，沿途的每台路由器都会为它做两件事：**选路** 和 **登记转发表**。在这一步，路由器不仅建了表，还为这条未来的连接**预留了专属的带宽和内存缓冲区**
- 主机 B 收到呼叫请求，如果主机 B 此时有空（同意连接），它就会发回一个确认包，叫做 **“呼叫接受（Call Accepted）”**。
- 这个确认包会**严格**沿着刚才开辟出来的路径（B $\rightarrow$ R2 $\rightarrow$ R1 $\rightarrow$ A）**倒着走回去**。沿途的路由器收到确认包后，正式激活（使能）刚才登记的那行转发表项。
- 当“呼叫接受”确认包最终完好无损地回到 **主机 A** 手中时，虚电路正式建立。主机 A 发出的所有后续数据包，**都不再需要写主机 B 的长地址**。只要在包头贴上 **VC 号**即可。

## 数据传输阶段

- 网络层（或适配层）会将大数据切分成固定或变长的块，并在每个数据包的头部直接填入在建立阶段就协商好的**第一段链路的 VC 号（出方向标签）**，随后将其送入指定的物理接口。
- 当贴有标签的数据包到达路径上的中间路由器时，以`[输入接口 + 输入 VC 号]`作为联合索引，去检索内存中早已固化好的转发表。路由器读取到该表项对应的 `[输出接口 + 输出 VC 号]` 后，立刻用**新 VC 号**强行覆盖掉数据包头部的**旧 VC 号**。数据包被直接推送到对应的输出接口，发射给下一跳。
- 当最后一个中间节点将数据包送达目的地（宿端）时，识别出这是属于哪条已建立连接的 VC 号，随后直接将头部的 VC 号等网络层控制信息剥离，由于虚电路保障了所有数据包在物理路径上是**绝对排队、有序前进**的，宿端无需担心乱序问题，直接按照收到的先后顺序，将数据净荷（Payload）拼接、还原成原始的业务数据，递交给上层应用。

## 虚电路拆除阶段

- 源端向网络中注入一个特殊的控制信令包，通常称为 **“释放连接请求（Clear Request）”** 或 **“拆除信令”**。
- 拆除信令包会严格沿着之前建好的虚电路路径（R1 $\rightarrow$ R2 $\rightarrow$ ...）依次流经每一个中间路由器。每台路由器在收到这个信令后，立刻将此前为这条虚电路**死死霸占、锁定的硬件资源（如专属带宽、特定优先级的硬件队列、缓冲区内存）全部释放**，路由器在自己的 VC 号转发表中，将对应的那一行 `[输入接口 + 输入 VC 号] ➔ [输出接口 + 输出 VC 号]` 的记录**直接删除**，路由器完成本地的卸载工作后，将信令转发给下一跳，直到信令到达终点。
- 宿端（接收方）收到释放信令后，得知对方已停止发送，它也会清理掉本地关于该连接的控制状态，并向发起端回传一个 **“释放确认（Clear Confirmation）”** 信令。

## 网络层与运输层连接建立区别

- 运输层的连接建立：**只涉及两个端系统**，相互协商通信并共同确定连接的参数。**网络中的路由器并不知道该运输层连接**。
- 网络层虚电路建立：**沿两个端系统之间路径上的路由器都要参与虚电路的建立，且每个路由器都完全知道所经过的所有虚电路。**

## 信令报文与信令协议

- **信令报文（Signaling Packet）**，就是网络中专门用来**传输控制信息、管理命令和状态通知**的特殊数据包。
- **信令协议**：用来交换信令报文的协议。

# 数据报网络

- 数据报网络（Datagram Network）是计算机网络层中一种 **无连接（Connectionless）** 的数据传输模型。
- 路由器没有端到端连接的状态，网络层无呼叫建立，分组使用目的主机地址转发，相同源和目的地的分组可能采用不同的路径
- 典型例子：Internet

## 传输过程

- 当你要发送一个大文件时，网络层会把它切成很多个小的数据报。发送端会在**每一个数据报**的头部，都封装上完整的**源 IP 地址**和**目的 IP 地址**。并送入网络，经过若干中间路由器转发分组，直到目的地。
- **路由器转发方法**：根据到达分组的目的地址在转发表中查询，找到相应的输出链路接口，并将分组转发出去。
- **转发表**：每台路由器有一张。**目的地址与链路接口的映射表。**（转发表中的表项数与地址位数有关，每个可能的地址对应一项。）

## 转发表与最长前缀匹配

数据报转发表采用了“网络前缀（网段）聚合”的设计。
它的基础结构主要包含两列：

|**目的网络前缀 (Destination Address Range)**|**输出接口 / 下一跳 (Link Interface / Next Hop)**|
|---|---|
|`11001000 00010111 00010000 00000000/21` (即 200.23.16.0/21)|接口 0|
|`11001000 00010111 00011000 00000000/22` (即 200.23.24.0/22)|接口 1|
|`0.0.0.0/0` (默认网关，代表剩余所有未知世界)|接口 2|

### 最长前缀匹配（Longest Prefix Match）

- 给定目标IP地址,**在转发表中查找匹配表项时，使用最长前缀匹配。**
- 不存在匹配：选择“其他”项对应的链路转发

# 数据报网络与虚电路网络

- 虚电路服务：
	- 网络功能复杂，端系统设备简单。
	- 呼叫建立及每次呼叫的状态要在网络中的路由器上维持，比面向数据报的网络要复杂
- 数据报服务：
	- 网络层服务模型简单。
	- 端系统功能复杂：高层实现许多功能，如按序传送、可靠数据传输、拥塞控制与DNS名字解析等
	- 对网络层的需求最小，使得互连使用各种不同链路层技术的网络变得更加容易
	- 许多应用都在位于网络边缘的主机（服务器）上实现。
