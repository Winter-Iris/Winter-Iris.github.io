**CDN** 的全称是 **Content Delivery Network**，即**内容分发网络**。

如果把互联网比作一个巨大的快递系统，**源站服务器**（Origin Server）就是厂家的总仓库。如果所有人都去总仓库提货，路途遥远会导致物流极慢，且仓库门口会堵死。**CDN** 就像是在全国各地设立的**前置仓（分仓库）**，让你能从家门口的仓库直接拿货。

在没有 CDN 的情况下，访问一个网站会面临以下问题：
- **物理距离导致的延迟：** 信号传输受物理距离限制（光速限制）。跨越半个地球的访问延迟（RTT）非常高。
- **网络拥塞：** 必经的骨干网路由器如果负载过高，会导致丢包。
- **源站压力：** 如果所有用户直接请求源站，服务器的带宽和 CPU 会被瞬间压垮（例如抢购活动或突发新闻）。

## CDN 的核心组成

1. **源站 (Origin Server)：** 发布内容的原始服务器。
2. **边缘节点 (Edge Server / Cache Server)：** 分布在世界各地、离用户最近的缓存服务器。
3. **调度系统 (Global Load Balancer)：** 负责决定把用户的请求分配到哪个边缘节点。

## 工作流程

### 智能调度（DNS 重定向）

1. **用户发起请求：** 你在浏览器输入 `video.example.com`。
2. **DNS 解析：** 你的请求到达 DNS 服务器。由于该域名接入了 CDN，DNS 不会直接返回源站 IP，而是返回一个指向 **CDN 负载均衡器** 的 CNAME 记录。
3. **最优分配：** CDN 负载均衡器通过你的 **IP 地址** 判断你的地理位置（比如：北京市朝阳区），并检查各个边缘节点的健康状态和负载。
4. **访问边缘节点：** 浏览器拿到 CDN 节点的 IP，直接向该节点请求视频数据。
5. **命中 (Cache Hit)：** 如果该节点已经缓存了该视频，它会直接秒传给你。
6. **未命中与回源 (Cache Miss & Fetch)：** 如果该节点没有这个视频，它会向**上一级节点**或**源站**请求数据，将其缓存到本地，然后再发给你。
