# 最大传输单元MTU

- 网络链路存在MTU (最大传输单元)—**链路层数据帧可封装数据的上限**
- 大IP分组向较小MTU链路转发时，可以被分片
	- 1个IP分组分为多片IP分组 ，IP分片到达目的主机后进行“重组”

# IP分组


## 标识符 (Identification) —— 占 16 位 (Bits)

- 用于标识一个IP分组
- IP协议利用一个计数器，每产生IP分组计数器加1，作为该IP分组的标识

## 标志位 (Flags) —— 占 3 位 (Bits)

- **第 1 位：保留位 (Reserved)**
    - 目前固定为 `0`，留给未来开发使用。
- **第 2 位：DF 位 (Don't Fragment - 请勿分片)**
    - **`DF = 1`**：**禁止分片**。如果中间路由器发现它的尺寸超过了 MTU，又不能切，路由器就会直接把这个包**丢弃**，并向源头发送 ICMP 报错信。
    - **`DF = 0`**：准许分片。路由器遇到大包可以随时动手切。
- **第 3 位：MF 位 (More Fragments - 更多分片)**
    - **`MF = 1`**：代表“**后面还有货**”。接收端看到它，就知道这只是其中一个碎片，后面还有属于这个 ID 的兄弟碎片在路上，必须继续等待。
    - **`MF = 0`**：代表“**我是最后一个**”。接收端看到它，就知道全套拼图的最后一块已经到齐了，可以准备收尾重组了。

## 片偏移 (Fragment Offset) —— 占 13 位 (Bits)

- 一个IP分组分片封装原IP分组数据的相对偏移量（记录了当前这个碎片所携带的“用户数据（Payload）”，在原始未切片的大包数据中，**距离起点的相对距离（字节数）**。）
- **片偏移字段以8字节为单位**

## 计算


假设原始未分片的 IP 大包参数如下：
- $L$：原始大包的总长度（包含 IP 头部和数据）
- $head$：原始 IP 头部的长度（通常为 20 字节）
- $\text{Original\_ID}$：原始大包的标识符
- $\text{MTU}$：当前链路的最大传输单元

### 最大载荷（一个分片可封装的最大数据）

- **一个分片可封装的最大数据**应该是8的倍数
$$\text{Max\_Payload} = \lfloor \frac{\text{MTU} - \text{head}}{8} \rfloor \times 8$$
### 需要划分的片数 

- 所以需要的总片数为

$$N = \lceil \frac{\text{L} - \text{header}}{\text{Max\_Payload}} \rceil$$

### 片偏移字段取值

- 每片的片偏移字段取值，对于切分出来的**第 $i$ 个分片**（$i$ 从 0 开始计数，即 $i = 0, 1, 2, \dots$）：
- 真实字节偏移量为
$$\text{Byte\_Offset}_i = i \times \text{Max\_Payload}$$
- 片偏移字段实际填入值为

$$\text{Offset}_i = \frac{\text{Byte\_Offset}_i}{8} = \frac{i \times \text{Max\_Payload}}{8}$$

### 每片的总长度字段

对于分片 $i$（$i = 0, 1, 2, \dots, N-1$），其**总长度字段 $\text{Total\_Len}_i$** 的分段函数为：

$$\text{Total\_Len}_i = \begin{cases} \text{Max\_Payload} + 20, & \text{if } 0 \le i < N - 1 \quad \text{(前 } N-1 \text{ 片)} \\ \text{Total\_Len} - (N-1) \times \text{Max\_Payload}, & \text{if } i = N - 1 \quad \text{(最后一片)} \end{cases}$$

其中总片数 $N = \lceil \frac{\text{Total\_Len} - 20}{\text{Max\_Payload}} \rceil$。

### 每片的MF标志位


第 $i$ 个分片的 **$\text{MF}_i$ 标志位** 的分段函数为：

$$\text{MF}_i = \begin{cases} 1, & \text{if } 0 \le i < N - 1 \quad \text{（前 } N-1 \text{ 片，代表后面还有碎片）} \\ 0, & \text{if } i = N - 1 \quad \text{（最后一片，代表后面没有碎片了）} \end{cases}$$


# IPv4


- 节点在互连网中分配的一个**唯一地址**。用于把分组送到目的IP网络。
- IPv4长度为32比特。
- IPv6中IP地址扩展到128位

## 点分十进制

- 32 位的地址被平均分成 4 个“字节”（每个字节 8 位），每个字节转换成十进制数字（范围从 `0` 到 `255`），中间用点隔开。
- `11000000 10101000 00000001 00000001` = `192 . 168 . 1 . 1`

## IP 地址结构

- IP地址由 **网络号 + 主机号** 组成
- **网络号（Network ID）**：标识设备所在的网络。（指明主机所在物理网络的编号）
- **主机号（Host ID）**：标识该网络内的具体某台主机或路由器接口。（主机在物理网络中的编号）

## 子网掩码

和 IPv4 地址一样，子网掩码在计算机内部也是一个 **32 位的二进制数字**。
但它有一个极其霸道的硬性规定：**所有的 `1` 必须连在一起写在前面，所有的 `0` 必须连在一起写在后面。** 绝对不允许出现 `1010` 交替的情况。
- **连续的 `1`**：代表这部分对应的 IP 地址是**网络号**（划分网段）。
- **连续的 `0`**：代表这部分对应的 IP 地址是**主机号**（划分具体的电脑）。


$$\begin{array}{rcc} \text{IP 地址:} & \texttt{11000000.10101000.00000001.00000101} & (192.168.1.5) \\ \land \quad \text{子网掩码:} & \texttt{11111111.11111111.11111111.00000000} & (255.255.255.0) \\ \hline \text{网络地址:} & \texttt{11000000.10101000.00000001.00000000} & (192.168.1.0) \end{array}$$

**结果：** 经过子网掩码的遮罩，后面 8 位的主机号被“抹零”了。计算机得出结论：**我当前所在的网段是 `192.168.1.0`**。

## 子网

- 无需路由器介入，子网内各主机可以在物理上相互直接到达
- 具有相同的地址前缀
- 在一个子网内部的各设备其地址高位部分相同
- 判断一个子网范围：将每一个接口从主机或者路由器上分开，构成了一个个网络的孤岛，每个相互独立的网络部分被叫做子网

## 特殊地址

### 环回地址（Loopback Address）

- `127.0.0.0/8` 整个以 `127` 开头的 1600 万个地址全部都是环回地址。当你的电脑向 `127.0.0.1` 发送数据包时，**这个数据包根本不会流向网线或 Wi-Fi 天线**。网卡驱动在网络层看到 `127` 后，会直接把这个包“掉头”送回自己的应用层。

### 私网地址（Private Address）

- 在 A、B、C 三类网络中各挖出了一块地址，规定**公网路由器绝对不转发这些流量**，它们只能在企业或家庭局域网内部使用。

|**类别**|**私网地址范围**|**常见应用场景**|
|---|---|---|
|**A 类**|`10.0.0.0` ～ `10.255.255.255` (`10.0.0.0/8`)|大型企业内网、数据中心内部|
|**B 类**|`172.16.0.0` ～ `172.31.255.255` (`172.16.0.0/12`)|学校校园网、中型企业|
|**C 类**|`192.168.0.0` ～ `192.168.255.255` (`192.168.0.0/16`)|**家用路由器默认网段**（如 `192.168.1.1`）|
- 它们可以**在全球无数个家庭里重复使用**。你家的手机 IP 是 `192.168.1.5`，你邻居家的手机 IP 大概率也是 `192.168.1.5`。它们互不干扰，只有在通过路由器（NAT 技术）上网时，才会换上唯一的“公网外衣”。

### 广播地址：`255.255.255.255`

- 这是一个 32 位全为 `1` 的终极地址。当一台电脑向 `255.255.255.255` 发送数据包时，**当前局域网内的所有物理设备都会强制接收并拆开这个包**。
- 由于广播包杀伤力太大，**路由器会死死挡住这个包**，绝对不允许它跑到别的网段去，因此它只在当前这一个局域网（广播域）里有效。

### `0.0.0.0`

- 在 **服务监听（bind）** 时： `0.0.0.0` = 绑定到本机所有 IPv4 地址
- 如果程序监听：`0.0.0.0:8080`，任何网卡进来的请求都能访问这个端口
- 在路由表里：`0.0.0.0/0`表示“所有IP地址”（默认匹配规则）也就是**默认路由**。不知道往哪走的流量走这里。



# CIDR（Classless Inter-Domain Routing，无分类域间路由选择）

在过去，IP 地址被硬性规定为三种主要规格：
- **A 类网络**：前 8 位是网络号，后 24 位是主机号。一个网段可以容纳 **1600 万**台设备。
- **B 类网络**：前 16 位是网络号，后 16 位是主机号。一个网段可以容纳 **65,534** 台设备。
- **C 类网络**：前 24 位是网络号，后 8 位是主机号。一个网段只能容纳 **254** 台设备。

- CIDR 的核心思想非常纯粹：**彻底消除了 A、B、C 类网络的概念，网络号（网络前缀）不再局限于只能是 8 位、16 位或 24 位，而是可以变成任意长度！**
- 为了配合这种灵活性，CIDR 引入了“斜杠记法”（CIDR 记法）：
$$\text{IP 地址} \, / \, \text{网络前缀所占的位数}$$
- 举个例子：`192.168.10.0/22`：这个 `/22` 告诉我们，在这个 32 位的 IP 地址中，**前 22 位固定为网络前缀（网络号）**，剩下的 $32 - 22 = 10$ 位用来分配给主机。

- 优点：
	- 提高IPv4 地址空间分配效率
	- 提高路由效率：将多个子网聚合为一个较大的子网，构造超网(supernetting)
	- 路由聚合 ( route aggregation)

# 路由聚合

- **路由聚合（Route Aggregation）**，也被称为**构造超网（Supernetting）**，是网络层 CIDR 架构下的核心技术。
![pasted-image-1782374910995.webp](https://files.seeusercontent.com/2026/06/25/huH4/pasted-image-1782374910995.webp)

- **路由聚合**（又称路由汇总）是==将多条连续的、具有相同前缀的明细路由合并为一条聚合路由发布出去的技术==。它可以有效减小路由表规模，加快路由查找速度，并提升网络稳定性

# DHCP

- DHCP（Dynamic Host Configuration Protocol，**动态主机配置协议**）
- 目标: 允许主机在加入网络的时候，**动态地从服务器那里获得IP地址**
	- 可以更新对主机在用IP地址的租用期-租期快到了 
	- 重新启动时，允许重新使用以前用过的IP地址 
	- 支持移动用户加入/退出该网络（短期在网）

- DHCP不仅仅可以返回在一个子网中分配的IP地址 
	- **默认网关**：第一跳路由器IP地址（对于客户端来说要将分组发 向外部网络所需要经过的第一跳路由器的IP地址） 
	- **DNS服务器的域名和IP地址** 
	- **子网掩码**（指示IP地址中哪些位是网络号，哪些位是主机号）

## 工作流程

- 主机广播“DHCP discover” 报文。
	- 当客户端接口激活并启动 DHCP 进程时，由于它没有 IP 地址，也无从知晓服务器的位置，它会初始化一个**广播报文**
	- 客户端状态机进入 **INIT** 状态，向当前局域网（广播域）全员发送 DISCOVER 报文。
- DHCP 服务器用 “DHCP offer”提供报文响应
	- 局域网内的 DHCP 服务器收到广播后，会检查自身的**地址池（Address Pool）**，并为该客户端预留一个可用的 IP。
	- 服务器向客户端回应 OFFER 报文，此时，服务器在报文的 **`yiaddr` (Your Internet Address)** 字段中填入拟分配的 IP 地址，并在 `Options` 携带子网掩码（`Option 1`）和续租租期（`Option 51`）。
- 主机请求IP地址：发送 “DHCP request” 报文
	- 由于局域网内可能存在多台 DHCP 服务器，它们可能都会回应 OFFER。客户端通常会**选择最先到达的那个 OFFER**，并再次发送一个**广播报文**做出回应。
	- 报文中会携带 `Option 54`（服务器标识符），明确指出它接受了哪台服务器的地址。被选中的服务器会将该地址转为正式分配，而未被选中的服务器则可以释放此前预留的 IP，重新放回地址池。
- DHCP服务器发送地址：“DHCP ack” 报文
	- 被客户端选中的 DHCP 服务器收到 REQUEST 报文后，确认该地址依然可用，便会建立正式的租约记录。
	- 服务器在本地数据库将该 IP 的状态修改为 **Binding（已绑定）**，并向客户端发送 ACK 确认报文（`Option 53 = 5`）。在该报文中，服务器会附带下发其他关键网络参数

# NAT

- NAT（Network Address Translation，网络地址转换）
- 内网设备想要上互联网时，不能直接用私网 IP 出去（因为外网服务器找不到回来的路）。必须在出口路由器上，通过 **NAT** 把私网 IP 统一换成运营分给你的、全球唯一的**公网 IP**，然后再发送到互联网。

- NAT 的核心是一张动态维护的 **NAT 转换表（NAT Mapping Table）**
- NAT 路由器必须 (透明地)实现:
	- 外出的数据报：**替换每个外出数据报的（源IP地址，源端口号）**， 将之变换成（NAT外部IP地址，新端口）
	- 远程的客户端/服务器将会回应该数据报，目标地址：（NAT外 网IP地址，新端口号）
	- **记下**（在NAT转换表中）每一个（源IP内网地址，源端口号） 到 （NAT 外网IP地址，新端口号）的**映射对**
	- 进来的数据报：**替换每个到达该网络数据报的目标字段**（NAT外网 IP地址，新端口号），将之替换成在NAT 表格中的（源内网IP地址， 源端口号）

# NAT 穿透（NAT Traversal）

- NAT 穿透，就是为了让两台都在内网的主机，不通过第三方服务器中转，直接建立“端到端（End-to-End）”的直接通信通道。
- NAT 穿透就是：利用 NAT“允许外出连接”的特性，通过中间服务器交换地址，让两端主动互相发包，从而建立 P2P 直连通信。

## UDP 打洞

- 电脑 $A$ 和电脑 $B$ 同时主动向公网上的 **STUN 服务器** 发送一个 UDP 探测包。
- 服务器记录：A 的公网映射地址，B 的公网映射地址
- 服务器互相告诉对方地址
- $A$ 向 $B$ 的外网身份发送一个 UDP 数据包。$B$ 向 $A$ 的外网身份发送一个 UDP 数据包。
- 一旦 $A$ 收到了 $B$ 的包，$A$ 再次回包时，也能顺利穿透 $B$ 的路由器。此时，那台公网的 STUN 服务器就可以功成身退了。$A$ 和 $B$ 之间直接建立了一条**跨越千山万水的 P2P 直连通道**，传文件速度可以直接飙到两家宽带的物理上限。

# ICMP协议

- **因特网控制报文协议ICMP**（Internet Control Message Protocol）是一个差错报告机制，是TCP/IP协议簇中的一个重要子协议，通常被IP层或更高层协议（TCP或UDP）使用，**属于网络层协议**，主要用于**在IP主机和路由器之间传递控制消息**，用于报告主机是否可达、路由是否可用等。这些控制消息虽然并不传输用户数据，但是对于收集各种网络信息、诊断和排除各种网络故障以及用户数据的传递具有至关重要的作用。
