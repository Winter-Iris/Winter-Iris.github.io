- 在 OSI 七层模型里,传输层是第 4 层;在更常用的 TCP/IP 模型里,它位于**应用层之下、网络层之上**。这个位置决定了它的使命:**向上为应用程序提供通信服务,向下利用网络层的能力**。

- 除了上面这个最基本的**进程到进程通信**,传输层还可以(可选地)向应用层提供一些"高级服务",把不可靠的网络包装成可靠的通道。

- **可靠数据传输(Reliable Data Transfer)**——网络层只是"尽力而为",数据包可能丢失、乱序、损坏、重复。传输层通过序列号、确认应答(ACK)、超时重传、校验和等机制,让上层应用感觉自己在使用一条**没有差错、按序送达**的可靠通道。

- **流量控制(Flow Control)**——防止快的发送方淹没慢的接收方。比如服务器疯狂发数据,而客户端是个旧手机处理不过来,传输层会让发送方"慢一点"。

- **拥塞控制(Congestion Control)**——防止发送方淹没**网络本身**。当网络中路由器队列开始堆积、丢包率上升,传输层会主动降速,这是整个互联网得以稳定运行的关键机制之一。

# 多路复用与解复用

### 起点:套接字(Socket)

应用进程不能直接和"网络"对话,它通过一扇**门**和传输层交换数据,这扇门就叫**套接字**(socket)。每个套接字都有一个端口号作为标识。
那么:
- **复用(Multiplexing)** = 发送端的活儿:从多个套接字收集数据,给每段加上含端口号的头部,打包交给网络层。
- **分用(Demultiplexing)** = 接收端的活儿:网络层把段递上来,传输层根据头部里的端口号,把数据投到正确的套接字。
- 不论 TCP 还是 UDP,每个报文段(segment)的头部都有两个固定字段:**源端口号**和**目的端口号**(各 16 位,所以端口号范围 0–65535)。这就是分用的"地址簿"。

## 多路复用 (发送端：自底向上封装)

当你的主机上有多个应用程序同时发送数据时，传输层（TCP 或 UDP）会执行以下操作：
1. **数据收集**：从不同的 **套接字 (Socket)** 接收来自应用层的数据块
2. **添加头部**：为每个数据块封装传输层头部信息。其中最重要的字段是 **源端口号** 和 **目的端口号**。
3. **移交网络层**：将封装好的段（Segment）交给网络层（IP层），由 IP 层添加 IP 地址并将其发送出去。

## 解复用 (接收端：精准投递)

当目标主机接收到数据包时，传输层负责根据头部信息将数据“分流”给正确的进程。根据协议的不同，解复用的逻辑有所区别：

### UDP 分用:看(目的 IP, 目的端口)就够了

- UDP 套接字由一个**二元组**唯一标识:`(目的 IP, 目的端口)`。
- 也就是说,只要两个 UDP 报文段的目的 IP 和目的端口相同,**不管它们来自哪里**,都会被投递到**同一个套接字**。源 IP 和源端口只是写在头部供上层应用参考(比如让服务器知道"该回复给谁"),分用过程并不使用它们。

### TCP 分用:必须看完整四元组

- TCP 套接字则由一个**四元组**唯一标识:`(源 IP, 源端口, 目的 IP, 目的端口)`。
- 这意味着:即使两个报文段的目的端口相同,只要源 IP 或源端口不同,它们就会被投递到**不同的套接字**。
